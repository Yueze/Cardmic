# Cardmic firmware

M5Stack's factory firmware for the Cardputer ADV
([m5stack/M5Cardputer-UserDemo](https://github.com/m5stack/M5Cardputer-UserDemo),
branch `CardputerADV`) with the Cardmic app added. The stock boot screen,
launcher and apps are unchanged.

## What Cardmic adds

| Path | What |
|---|---|
| `main/apps/app_cardmic/app_cardmic.cpp` | The app: audio pipeline, UI, Wi-Fi setup, settings |
| `main/apps/app_cardmic/cardmic_usb.c` | USB Audio Class 2.0 microphone, plus the talk-key HID keyboard (TinyUSB) |
| `main/apps/app_cardmic/cardmic_net.c` | Wi-Fi streaming and screenshots, see [PROTOCOL.md](../protocol/PROTOCOL.md) |
| `main/apps/app_cardmic/cardmic_ota.c` | Over-the-air updates from GitHub Releases |
| `main/apps/app_cardmic/cardmic_pair.c` | Pairing codes and key derivation |
| `main/apps/app_cardmic/assets/` | App icon, generated by `tools/make_cardmic_icon.py` |
| `CMakeLists.txt` | `PROJECT_VER` (the one version number) and USB audio options |
| `partitions.csv` | Two app slots for OTA updates |
| `sdkconfig.defaults` | Bootloader rollback |
| `main/main.cpp`, `main/apps/apps.h` | Registers the app; confirms a freshly updated image |

## Build

Requires [ESP-IDF v5.4.2](https://docs.espressif.com/projects/esp-idf/en/v5.4.2/esp32s3/get-started/).

```bash
python3 fetch_repos.py   # M5GFX, M5Unified, mooncake, smooth_ui_toolkit
idf.py build
./tools/package.sh       # release assets in dist/
```

## Development builds

`idf.py -B build-dev -DCARDMIC_DEV=1 build` adds remote tools for working on
the app without touching the device, active only while Cardmic is open:
`CARDMIC_DEV_DOWNLOAD` (reboot into the ROM bootloader for flashing),
`CARDMIC_DEV_KEY <hex> <0|1>` (inject a key) and `CARDMIC_DEV_CODE` (read the
pairing code), all over UDP 41234. Release builds never contain them.

## Flash during development

Full flash (first time, or after changing the partition table), with the
device in download mode (power off, hold G0, plug in USB, release):

```bash
idf.py -p PORT flash
```

While the stock launcher is running, the USB serial port is available and
you can update just the app without touching the buttons:

```bash
python -m esptool --chip esp32s3 -p PORT --before default_reset --after watchdog_reset \
    write_flash 0xd000 build/ota_data_initial.bin 0x10000 build/cardputer-adv.bin
```

Writing `ota_data_initial.bin` makes the device boot the first slot even if an
OTA update had switched it to the second. Use `--after watchdog_reset`: a
plain hard reset over USB leaves this board in the ROM bootloader.

## Release

1. Bump `PROJECT_VER` in `CMakeLists.txt`.
2. Tag `vX.Y.Z` and push. CI builds the firmware and attaches
   `cardmic-ota.bin` and `cardmic-X.Y.Z-full.bin` to the GitHub release.
3. Devices find the new version under Settings > About > Check update.

The asset name `cardmic-ota.bin` is part of the device's update contract.
